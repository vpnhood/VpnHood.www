# VpnHood WWW — Project Instructions

Marketing site for VpnHood (free, secure, open-source VPN). Static **Jekyll** site ported from a **Helix Ultimate** (Joomla) template: every page is a standalone `index.html` with front matter (`layout: none`) that includes a shared header/footer. The folder path **is** the URL (`free-vpn/download/index.html` → `/free-vpn/download/`); no `.html` URLs, no `permalink:`. The page chrome (`#sp-header`/`#sp-footer`/`.body-wrapper`) and `assets/css/helix-theme.css` are still Helix.

This file is the binding summary of what every task needs. Each area's rules live in `.claude/rules/` and load on their own when a file of that area is read or edited; each links a doc in `.docs/` with the full explanation, history and troubleshooting — read it before changing that area.

## Hard rules

- **Pushing `main` deploys production** (GitHub Pages via `.github/workflows/jekyll.yml`). After a deploy, purge the Cloudflare cache for `www.vpnhood.com`.
- **Copy lives in `_data/i18n/en/<page>.json`, never in page markup.** Edit copy in the JSON, structure in the page.
- **Every internal link is `href="{{ vh_base }}/<path>/"`** — language-prefixed and trailing-slashed. Exceptions: legal pages (never prefixed), `/assets/...` and external URLs (never slashed).
- **Never auto-format `_includes/header.html` or `_includes/footer.html`** — the header intentionally leaves `<html>`, `<body>`, `.body-wrapper`, `.body-innerwrapper` open (div balance net **+2**) and the footer closes them. `.prettierignore` covers both.
- **Never edit** `_site/` (output), `_sass/vendor/bootstrap/` (vendored source), or `_data/i18n/<lang>/` for any language but `en` (generated by vhtranslator, overwritten on the next run).
- **Never write a raw colour** (`white`, `#fff`, `rgba(255,255,255,…)`) in our SCSS — use `--vh-*` tokens or the brand ramp, or the light theme has nothing to re-point.
- **Never hot-link a public CDN** — the Great Firewall blocks cdnjs, unpkg and every Google host. Vendor into `assets/js/vendor/` or `assets/css`.
- **Every `meta_title` contains "VpnHood!"**, and [.docs/seo-and-semantic-html.md](.docs/seo-and-semantic-html.md) is binding for any markup change (a shared standard kept byte-identical with `paymenthood-www` — edit both copies together).
- **Light-mode art comes only from `python tools/make-light-art.py`** — never hand-author a `*-light.*` file or a per-image CSS filter.
- **Verify both themes after any markup or CSS change**; the dark theme must stay pixel-identical.
- **`jekyll serve --watch` never reloads `_plugins/`** — restart it after a plugin edit. A `_data` change triggers a full rebuild (~15 s). **Generators must not stamp render-time data onto pages** — that rebuild renders fresh page objects, so the data vanishes in local preview while CI stays green.

## Build & deploy — [.docs/build-and-deploy.md](.docs/build-and-deploy.md)

`bundle exec jekyll build` / `bundle exec jekyll serve --livereload`. CI runs `vhtranslator` before every build, swaps any translation that changed a placeholder for its English source (`tools/check-placeholders.py --heal`) and commits the translations back (`[skip ci]`), syncs the legal pages from the VpnHood repo (fail-fast), fails on a self-link (`tools/check-self-links.py`) or on any internal link, anchor or asset that doesn't resolve in any of the 13 trees (`tools/check-links.py`; legal pages only warn), then publishes `_site`. `Gemfile.lock` must keep both `x64-mingw-ucrt` and `x86_64-linux`. `www` may or may not be Cloudflare-proxied; when it is, SSL mode must be **Full**. A retired URL goes in `_plugins/legacy-redirects.rb` (stubs for every language tree) plus a Cloudflare Single Redirect for a real 301 — enable the rule only once the target exists in production.

## Page anatomy

- Front matter: `layout: none`, `i18n: <page_key>` (names the data file), `nav_active` (`home | free-vpn | reseller | self-hosted | resources`; unset when not in the nav), optional `extra_css` (list; home uses `/assets/css/home.css`, content pages `/assets/css/custom.css`), `globe: true` on home only. **No `title`/`description`** — those are the `meta_title`/`meta_description` JSON keys, injected by `_plugins/i18n-meta.rb`. Legal pages are the exception: they declare both and have no `i18n`. Docs pages are ordinary pages that capture their article and hand it to `{% include docs.html article=vh_article %}`, which adds the breadcrumb and the section's sidebar from `_data/docs_nav.yml` — not a Jekyll layout, because a layout renders after the body, before `header.html` has assigned `vh_base` and `tc`. `_includes/docs-index.html` lists a section's pages with their `meta_description`. A docs page ends with **Next steps**: only what the reader does once its task is done, never the page they came from, an alternative to what they just did, a prerequisite, or a link back to the docs (owner, 2026-10-22).
- Body: `{% include header.html %}` → `{% assign vh_lang = page.lang | default: 'en' %}{% assign t = site.data.i18n[vh_lang][page.i18n] %}` → `<main id="sp-main-body">…</main>` rendering `{{ t.key }}` → `{% include footer.html %}`. Translatable attributes (`alt`, `placeholder`, `aria-label`) use `{{ t.* }}`; `class`/`href`/`data-*` never do. Inline HTML fragments (`<b>…</b>`, a whole `<a>`) may live inside a JSON string.
- Header/footer/offcanvas text is `{{ tc.* }}` from `_data/i18n/<lang>/chrome.json`, assigned once in `header.html`. Edit chrome copy there, never in the includes.
