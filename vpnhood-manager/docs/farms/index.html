Every project starts with Server Farm 1 (ProjectService); a new farm takes only a name, gets the project's default profile, PushTokenToClient on and a self-signed PublicInToken certificate with a made-up name, and has no token until a server reports a PublicInToken address (FarmTokenBuilder, TokenError in red under Name). The Server Farm field of Add a Server and of a new key shows only with more than one farm. A server with its own certificates can't move (ServerService); a moved server or key refuses the old farm's keys with an AccessError, on which nothing is pushed (SessionService). Push sends the key rebuilt from the farm's token on every reply but AccessError and AccessLocked, once every server with a PublicInToken address is Idle or Active, or at once for a key with only a domain (BuildResponseAccessKey). Farm token URLs: the encrypted token at each Publish Url, which keys carry; apps read them only after a failed connect (VpnHoodApp); Auto Upload Off, POST, PUT or PUT & POST, filled in from a GitHub, GitLab or Bitbucket Publish Url. A farm with a server can't be deleted; its keys go with it. The plan's farm and repo quotas are left out: production may set its own.
