SERVER v9.0.859. A server's status is ServerCache.CalculateState: NotInstalled until it first configures, then Error while it reports a config error, Lost once it has not reported for three status intervals and 15 s (the interval is 120 s by default; production's may differ, hence "every few minutes"), Configuring, Disabled, Idle, Active. New sessions go only to an enabled, not full server that is Idle, Active or Configuring (ServerSelectorService). The server card shows the error in red under Error; the Access Points card a red icon beside each port the server could not open (ServerStatusUpdater). The agent marks every access point missing from the server's report NotListening, and the server reports only the addresses it listens on, so the console shows those icons only on a Listen Yes address (console of 2026-10-29; the agent stops marking the others in its next release: finding 30 in the MANAGER improvements plan). The server retries its settings every minute (ConfigureInterval), and after a week of failures only every 30 minutes, with one try at each restart (ConfigErrorTracker). The SSH install dials public addresses only, answers sudo's prompt with the Login Password, and fails "Installation failed!" when /opt/VpnHoodServer has no publish.json; the console's error dialog shows the reply under Details. An install command stays valid: the server's authorization changes only when it is deleted. A farm whose token cannot be built keeps its old one and shows FarmTokenBuilder's message under its name; a farm that never had one gives every key "The server farm token has not been initialized properly." (GetRequiredServerToken): both checked on production's test project on 2026-10-28 with a throwaway farm, deleted after. The wiki's "Could not find any public access point for the ServerFarm" is that case; its message no longer exists. MANAGER's labels and messages are placeholders from _data/code.yml, filled in by copy.html. No screenshot: each state needs a broken server. No links to the GitHub wiki. The list of problems under the lead links to each one; each has a character drawn by tools/make-docs-heroes.py (trouble-.svg, the id its heading's), decorative, so alt="". {%- endcomment -%} {% capture vh_article %} {% include docs-hero.html art="vpnhood-manager/docs/hero-troubleshooting.svg" %}
