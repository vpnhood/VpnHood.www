SERVER v9.1.866 and the MANAGER of 2026-11-04 (agent 4.0.442), and checked against both sources, for issues #616 and #802 of VpnHood (owner, 2026-11-04: one page for a server whose IP changes, and artwork, not plain text). What it rests on: a server's status call from a new address of either IP version gives it a new config code, so it reconfigures, and Configure looks its public addresses up again (the agent's StatusIpTracker; VpnHoodServer). That is for Automatic Configuration only, and it compares each family with its own last status address, so a router that sends each connection out over another line flips it for good (the accepted limit in StatusIpTracker's comment). Automatic Configuration keeps each access point's TCP, UDP and QUIC ports through a change (the agent's GetBestTcpPort and its UDP and QUIC twins). Behind a router, the machine's private address is Private with Listen and the public one is Public without Listen, PublicInToken for the first (BuildServerAccessPoints). QUIC runs on a UDP port (Configure's GetFreeUdpPort). An app looks a key's name up only when the key marks it a valid host name (EndPointResolver.ResolveHostEndPoints), which MANAGER does only for a validated certificate (FarmTokenBuilder), and then tries the name's answers and the key's addresses alike. Port 80 answers Let's Encrypt on each TLS endpoint's address, so forwarding it to the machine is enough (Http01ChallengeService). A standalone server looks its address up only at start, and with IsValidHostName its keys carry the name too (FileAccessManager). The three diagrams are drawn twice by tools/make-docs-diagrams.py: left to right from a tablet up, top to bottom on a phone. The hero is tools/make-docs-heroes.py's dynamic_ip. The screenshots are real app UI, so they have no light variant; how to retake the ports one, and the certificate one it shares with certificates/, is in Vh/.user/docs/manager-test-projects.md.
