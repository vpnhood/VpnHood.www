--- layout: none i18n: vpnhood_server_docs_requirements nav_active: self-hosted extra_css: - /assets/css/custom.css --- {% include header.html %} {% assign vh_lang = page.lang | default: 'en' %}{% assign t = site.data.i18n[vh_lang][page.i18n] %} {%- comment -%} What a machine needs to run VpnHood! SERVER since v9.1.864, its first release on .NET 11. The distributions are those .NET 11 supports (supported-os.md in dotnet/core, glibc 2.27 on x64 and arm64), plus Amazon Linux and Arch; a version we did not test is listed on that support, and fixed if someone reports it (owner, 2026-11-03). Tested 2026-11-03 with v9.1.864's own install command, each to its service, its TUN adapter with NAT, and TCP 443: the Debian 13 cloud image as a VPS gets it (it had no ICU; the installer added it), and in systemd containers Ubuntu 22.04, 24.04, 26.04, Debian 12, 13, AlmaLinux 8, 9, 10, Rocky 9, CentOS Stream 10, Amazon Linux 2023, openSUSE Leap 16.0, Fedora 45 and Arch; Arch again 2026-11-06 on a Hyper-V VM, with a client connected through it. Alpine installs but cannot run the glibc build. Windows: Windows 11 Pro without Hyper-V answers New-NetNat with "Invalid class", so the server had no adapter and apps used Cloak Mode; the Containers feature did not bring WinNAT, Hyper-V did. Windows Server 2025 had WinNAT with neither. Names and versions are markup, as there is nothing in them to translate; the versions are dir="ltr", or an RTL page turns their list around. Every section is alike, the processor's included (owner, 2026-11-03: the page is all requirements, so none of them is a card): a title with its icon, then text. The icons of Linux, Docker and the distributions are the brands' own marks, one colour, from Simple Icons (CC0) in _includes/icons/brands/; Simple Icons has no Microsoft or Amazon mark, so Windows' is its four panes, drawn there, and Amazon Linux takes Linux's. One distribution per row, so each has its mark. The processor: since v9.1.864 the server runs on .NET 11, which refuses to start on an x64 processor below x86-64-v2 (CX16, POPCNT, SSE3, SSSE3, SSE4.1, SSE4.2), prints cpu_error and exits, and systemd restarts it forever. A VPS whose host gives it QEMU's basic kvm64 model hides them all, whatever the hardware. ARM64's minimum did not change. The check greps two of the six flags: kvm64 lacks every one, and a real processor with SSE4.2 and POPCNT has the rest.
