SERVER for a user without root, first moved from the GitHub wiki's How-to-run-VpnHood-Server-on-Linux-without-ROOT-access page (the www plan's wiki move, item 3). Since 2026-11-24 a release carries an installer for it, VpnHoodServer-linux-noroot.sh (the VpnHood repo's src/apps/Server/pub/Linux-NoRoot/install.sh, apart from root's installer on the owner's word), so the page leads with its command, a quick start as install/linux/ is: its questions and options are on installer-options/#user. It installs into ~/VpnHoodServer and starts at boot and updates itself by the user's own systemd services (lingering, which polkit lets a user turn on), else by cron; with neither it says so. Tested 2026-11-24 in containers and on the Debian 13 and Ubuntu 26.04 boxes as a plain user: install, a restart, an update, uninstall; on Debian 13 the installer refuses without ICU, which only root can add, hence the requirement. What works differently was run on 2026-11-24 as a plain user in WSL's Ubuntu, with v9.1.872: port 443 is refused (Permission denied) and 8443 works; the TUN device cannot be made, so apps use TCP forwarding, Cloak Mode; the OS settings fail; gen puts the port in the key. .NET's Ping, which the server forwards ICMP with, works for a plain user (ping_group_range), so the wiki's "no ping" is gone. QUIC is off unless set, so MsQuic, which only root installs, is not a limit here. No steps to run it by hand (owner, 2026-11-24: "agreed"): the installer covers every machine they would, and -noautostart -noautoupdate (installer-options/) leaves the same folder with nothing set up. No MANAGER promo: MANAGER installs its servers with root.
