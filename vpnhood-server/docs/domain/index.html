SERVER v9.0.856 and the MANAGER of 2026-10-19, checked against both sources. In MANAGER: Add makes a self-signed certificate, AutoSign gets Let's Encrypt's through the servers' HTTP-01 listener on port 80 and renews it, and the one PublicInToken certificate names every key of the farm; older keys still work while the certificate they pin stays in the farm. On a standalone server: no ACME, default.pfx is the only certificate, the key takes its name from it, and with IsValidHostName the key pins no hash, so older keys break but newer ones survive a renewal. Split out of /vpnhood-server/docs/ip-blocking/, which keeps the why. The page sells the trusted certificate, not the domain as a way to connect: a domain leads to the same address, and only a reverse proxy gets apps past a blocked one (owner, 2026-10-19), so it says nothing of moving the server and pointing the domain at it. A managed server's steps, with their screenshot, moved to /vpnhood-manager/docs/certificates/#domain, and the MANAGER promo right before the standalone steps links there (owner, 2026-10-22); this page is for a standalone server. Linux and Docker only, and no links to the GitHub wiki.
