SERVER v9.0.856 from a support answer, and checked against the server source in the VpnHood repo: the server binds its outgoing sockets to no address and has no setting for one, so the outgoing IP is the operating system's. Setting the two addresses is its own task, on /vpnhood-server/docs/ip-addresses/; this page says why and links there. MANAGER's screens are named as they read, and a managed server comes first, before a standalone one, wherever both appear. A domain is offered for its trusted certificate, not as a way past a blocked IP: it leads to the same address, and only a reverse proxy puts another one in front (owner, 2026-10-19). There is no advice to keep local sites off the server: a censor can watch from servers it runs abroad (owner, 2026-10-19). The censored-network settings are the server's, enforced on every user: without Cloak Mode the server ignores AllowQuicPacket and AllowUdpPacket, the users' QUIC and UDP, which are not the server's own UDP and QUIC that the empty lists turn off. A trusted certificate's host name hints at no VPN, as certificate logs are public, and is never a wildcard, which MANAGER refuses. Linux and Docker only: Windows servers are rare. No links to the GitHub wiki, which is being retired.
