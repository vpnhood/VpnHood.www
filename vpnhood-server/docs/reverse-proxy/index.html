Reverse proxies only, such as Cloudflare, which the server owner sets up (owner, 2026-10-19): an ordinary proxy, which a user sets in the app, is a different thing and does not belong on server pages, and neither does a TCP relay in front of the server. The proxy decrypts the connection and sees inside the tunnel, as TCP streams carry no encryption of their own inside TLS (only UDP does). The client tunnels over WebSocket by default, accepts any certificate that chains to an authority for the name, else the hash in its key, and looks the domain up only when the key marks it a valid host name; the domain's answers and the key's addresses are tried in a shuffled order, so an address left in the key is used as often as the proxy. A failed lookup falls back to the key's addresses. MANAGER builds a farm key with no address only from a validated certificate; a standalone server always puts its addresses in its keys. Behind a proxy that sends X-Forwarded-For, the server withholds its UDP and QUIC ports. The server answers ACME on plain HTTP port 80 only. The proxy's own steps serve both kinds of server; a managed server's steps in MANAGER, with their screenshot, moved to /vpnhood-manager/docs/access-points/#reverse-proxy, and the MANAGER promo right before the standalone steps links there (owner, 2026-10-22).
