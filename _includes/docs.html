{%- comment -%} Documentation pages: the breadcrumb, the section's sidebar and the article. A docs page is an ordinary page - it includes header.html first, so vh_base, tc and its own `t` exist while its copy renders - and hands its article over as a capture: {% capture vh_article %} ...headings, steps, terminal blocks... {% endcapture %} {% include docs.html article=vh_article %} Not a Jekyll layout: a layout renders after the page body, so the variables header.html assigns would not exist yet when the copy needs them. The sidebar is _data/docs_nav.yml keyed by the product folder; a section with no entry gets the article alone. The site search box (search-form.html) sits in the breadcrumb row, as docs sites keep search in their top bar, in view at every width: at the row's end from 992px up, on a line of its own under the breadcrumb below that. It is never inside the page list, or a phone would have to open the drawer to search. It scrolls away with the row, so Ctrl K or "/" brings the reader back to it, and on desktop the box shows that shortcut. Below 992px the sidebar is a drawer (Bootstrap's responsive .offcanvas-lg), opened by the button at the start of the breadcrumb row, so a phone opens every page at its title rather than at the page list. One copy of the links serves both widths; from 992px up Bootstrap hides the drawer's header and the button, and the sidebar is the plain column it always was.
